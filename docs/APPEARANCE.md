# Host theme and font-size candidate

**3.1.3 is local and unpublished.** Settings offers **Text size: 100%, 150%, 200%**. Selection previews the Settings font locally; Save persists it in the currently selected normal or validation profile. Cancel leaves saved settings untouched. On returning from Settings, the main view reloads the saved size; auxiliary local-tool dialogs load the same profile preference. Body fonts are 14 / 21 / 28 WPF logical units, captions 12 / 18 / 24, and headings 20 / 30 / 40. This changes actual text fonts, not a rendered transform, Windows DPI, Visual Studio editor fonts or global IDE options.

All extension windows and control templates reference Visual Studio **ToolWindowBackgroundBrushKey / ToolWindowTextBrushKey** via `DynamicResource`. They follow the host palette rather than maintaining a second independent Light/Dark preference. This uses the supported [Visual Studio themed WPF resource mechanism](https://learn.microsoft.com/en-us/visualstudio/extensibility/ux-guidelines/colors-and-styling-for-visual-studio?view=visualstudio); the [text brush key](https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualstudio.platformui.environmentcolors.toolwindowtextbrushkey?view=visualstudiosdk-2022) belongs to the VS Shell SDK.

Surfaces are opaque; windows do not request transparency, native blur, Acrylic or Mica. The explicit popup template disables popup animation. There are no custom storyboards or decorative transitions. Normal caret blinking and scrolling remain. Native OS frame/scrollbar rendering is host/platform owned and needs actual acceptance.

## Layout, controls and contrast limits

Settings has one vertical label/field flow, natural heights, wrapping explanation/error text, automatic vertical scrolling and a resize frame. Main uses vertically stacked read-only Original and Candidate/Changes sections, bounded scrollable text panes, a flexible-height instruction box, a full-width wrapping review checkbox and wrapping action groups. Local Add/Modify/Erase dialogs use the same themed/font resources and scroll/resize behavior. Code wrapping changes presentation only; it does not insert line breaks into the selected buffer or candidate.

TextBox, PasswordBox and ComboBox use explicit templates. This avoids default WPF popup/selection colors and the former black-on-dark combo text. Active boundaries and two-unit focus frames use **the same host text brush** as normal text. Textbox caret and list/popup text are explicit. Keyboard focus has an external outline; focused entries also show a thicker border. Tab headers and active checkbox/radio glyphs retain the host text/background pairing. Inactive button borders are subdued separately.

The old literal entry border `#3F3F46` against `#252526` had approximately **1.47:1** contrast; literal black combo text on that background was approximately **1.37:1**. Those pairs are no longer active style sources. No fixed numeric contrast is asserted for the new UI: host resources can change with theme/customizations. Because active boundaries share the text brush/background pair, a measured text ratio of at least 4.5:1 also exceeds the 3:1 boundary requirement. **Actual Light/Dark/high-contrast host colors, selected-text colors, focus/dropdowns and OS-owned scrollbar/frame contrast must still be measured natively.** Source bindings are not a rendered WCAG certification.

## Settings compatibility and verification

- Both existing storage paths add optional `TextScalePercent`. Legacy v2 normal and v1 validation files default to 100% without a rewrite. Legacy normal plaintext-key migration still moves to DPAPI v2 atomically and preserves a valid saved font size without creating a plaintext backup.
- Invalid save requests are rejected before writing/protecting replacement data. Unsupported JSON type/value/duplicate fields stop loading and preserve the existing main file; a bad font value cannot silently trigger key migration. Failed replacement leaves previous encrypted bytes/validation JSON intact and cleans the unique temporary file. Existing `.bak` files are not reset or migrated by this extension.
- The established recovery path remains explicit: unreadable normal/validation settings show the recovery explanation, and **Save replaces** them after the user re-enters valid fields. Cancel preserves them. This is not an automatic downgrade or silent reset of malformed preferences.
- Appearance does not change the review/candidate/current-selection guards, source buffer contents, provider recipients, credential-clearing rule, response parser, consent/disclosure or request timeouts. Saved provider/model changes still take effect on the next send. Settings are unavailable while a request is busy as before.
- **83 source tests pass with zero skips**, including all prior 62 tests. Real DPAPI and the previous production-path TCP/chunked protocol tests are retained. New file-based persistence and view-model reload tests are behavior checks; the changed-adapter binding test uses a clearly named stub and does not certify a model. Removing the font-save guard fails three tests, and suppressing font reload fails two; restored source passes again. No native IDE/standalone fixture/model was started for this appearance task.

## Native checks for the parent acceptance pass

Use the new VSIX only in a dedicated experimental IDE and an owned validation profile with a disposable editor file. Retain earlier packages and normal profile/registry baselines. Do not use personal keys or production source.

1. Open Settings, choose 200% and Save. Reopen Settings; confirm selection and actual enlarged text persist. Resize it to its 400-unit minimum width; Tab through provider/model/text size/Save/Cancel, open both dropdowns with keyboard, and confirm text/focus remains readable while scrolling reaches every field. Repeat at 150% and 100%.
2. At the main view's 440-unit minimum width and 200%, inspect Original, Candidate, Changes, status, instruction, review and all wrapped buttons using keyboard/scrolling. Open each local tool and verify fields, radio options and Save/Cancel actions fit. Original/candidate wrapping must not change source bytes or the replacement text.
3. Run local Remove duplicates, review it, then change only font size in Settings. Candidate, Changes, review and the unchanged-source guard must remain intact. Apply once and perform one editor Undo; verify the original buffer exactly.
4. In the dedicated IDE, check Light/Dark (and an available contrast theme) palettes. Record actual background/text/boundary/focus colors and ratios; inspect dropdown, password caret, selected text and OS scrollbars. Changing a host theme may require closing modal dialogs and reopening them. Dynamic resource bindings must use the new palette.
5. With the already authorized synthetic fixture started by the parent, run stream/401/malformed/timeout/cancel and recovery through the new scenario dropdown. First chunk must still appear while busy and Apply remain disabled; after final completion review enables Apply. This is protocol evidence, not a real model claim.
6. Restart the isolated IDE/profile to confirm persisted text size and no normal-profile/OS preference change. An owned locked/read-only settings save must show an error and preserve previous bytes; fix fixture permissions only after preserving its baseline.

Native 3.1.3 accessibility/layout and control-template usability are **pending**. Earlier 3.1.1 protocol and 3.1.2 dark-review screenshots are preserved historical evidence. Clean-machine install, another Windows account/SKU, screen-reader reading order and real-provider quality remain separate release gates.
